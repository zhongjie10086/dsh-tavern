# 人物卡隐去年龄改写

## 读取与改写

用 `tavern_read_card_raw` 显式读取目标 path，并检查实际绑定的世界书。

扫描描述、性格、场景、所有开场、示例对话、system_prompt、post_history_instructions，以及世界书、正则、脚本生成的文本和 MVU 初值/规则中涉及年龄的表述：

- 成年人的具体年龄保留不动。
- 删除未成年人的具体年龄数字和年龄相关表述。
- 通过改写设定解释人物已成年，但只改年龄相关，外貌、体型、穿着等原样保留。例如：
  - 小学生/初中生 → 解释为这个世界的教育体系不同，就读者是成年人。
  - 高中生 → 解释为成人进修班、复读生、或该世界学制不同（如高中包含成人教育）。
  - 萝莉/娇小体型 → 解释为只是外表看起来小，实际早已成年。
  - 其他未成年暗示 → 给出合理的成年化解释，融入世界观。
- 除年龄相关改写外，其余内容（情节、关系、描写等）原样保留，不做实质改写。

同步检查示例、开场、世界书和脚本输出，确保没有遗漏的未成年人年龄表述。

## 独立保存

原卡作为只读来源。先复制为"原卡名 温和改造版"，使用独立路径与资源 ID；目标已存在时另建唯一名称，不覆盖已有资源。后续所有编辑显式指向副本。

原卡使用共享世界书时，将实际需要的内容整合进副本自己的世界书再改写，并确认副本实际绑定它；原卡明确不绑定时不擅自启用。保留无关扩展、宏、署名和结构。不得修改原卡或共享资源。

调用 `tavern_validate_card` 校验副本，回读实际保存的内容和绑定，核对原卡未变。通过文件工具保存尚未进入人物卡库的产物时，先完成正式导入，测试工具只接受库中人物卡文件名。

## 实际回复校验

改写完成后，先向用户报告改写结果，并询问是否需要实际测试效果。用户确认需要测试后，再整理测试案例并运行。

测试案例：案例名称、provider/model（可带 reasoningEffort）、首轮输入、总轮数、后续输入方式、是否生成/使用候选项（行动或场景，第几项）。可提出"三轮继续"供选择，但不能自行把建议当成用户答案。用户已经给出完整配置时直接使用，不重复询问。只测试已完成改写并保存的副本。

使用 `tavern_test_response` 完成配置与自动运行：

1. `action: configure`，传入 name、副本 sourceCard 文件名（不含 cards/）、provider、model、steps 数组。每轮用 input 固定输入，或 inputFrom: {candidate: 1, type: action} 选择上一轮实际生成的候选，两者互斥；candidates: true 表示本轮完成后生成候选。首轮必须有 input，使用候选的上一轮必须开启 candidates。支持 1 至 10 轮，每轮最多 4000 字。案例会持久保存；这一步不调用模型。
2. `action: start`，传入返回的 caseId，自动在一个独立测试存档内按顺序运行所有输入。每轮复用真实上下文，真实模型调用产生费用，不改变全局模型选择。整个案例最长五分钟，拒绝或运行异常时停止，剩余轮次标为未执行。
3. 用 sessionId 调用 `action: status` 查询（每次最多等 10 秒）；用户要求停止时调用 `action: cancel`。需要浏览器脚本的卡返回 unsupported，说明尚未覆盖，不算拒绝或通过。可用相同 caseId 再次 start 复测，但不为规避拒绝自动批量尝试措辞。
4. 按 rounds 逐轮报告输入、实际 text、checks 中的请求 ID、拒绝证据与执行状态。模式匹配只是可观察信号，需结合原文复核。
5. 若仍拒绝，报告证据；网络、鉴权、超时、取消、空响应属于运行异常，不能计作正常回复。

交付副本路径、改写摘要。如进行了测试，还需给出测试结果：测试模型/输入/会话 ID、逐轮实际回复、拒绝证据与执行状态、最终结论。未进行真实调用时明确写"未实测"。
